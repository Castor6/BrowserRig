# BrowserRig Brand Direction

Use this reference when a visual task needs positioning, message hierarchy, or
copy decisions. It defines the current brief, not a finished identity system.

## Positioning

BrowserRig equips trusted agents with controlled access to the user's existing
browser. The formal product category is **local browser driver**. A bridge is a
useful relationship to visualize, but the local daemon is more than a temporary
pass-through and should not be described as one.

The product name is **BrowserRig**. Visual exploration may use option letters or
small working descriptors, but it must never propose or imply another product
or sub-brand name.

Message hierarchy:

1. It works with the browser the user already runs, including signed-in state.
2. An external agent decides what to do; BrowserRig executes deterministic
   browser control.
3. The extension and driver run locally and keep browser work visible.
4. Human checkpoints remain available for passkeys, 2FA, CAPTCHAs, and payment
   confirmation.

## Voice

Prefer direct, concrete language:

- "A local browser driver for trusted agents."
- "Give trusted agents controlled access to your existing browser."
- "Your browser. Your signed-in state. Controlled locally."

Avoid positioning BrowserRig as an AI sidebar, copilot, autonomous browsing
agent, chatbot, or magical assistant. Avoid unsupported security,
performance, popularity, or Store-ranking claims.

## Visual Character

Aim for precise, capable, direct, and human-controlled. Technical energy is
welcome; generic cyberpunk atmosphere is not. The identity should remain
recognizable without glow, depth effects, or explanatory copy.

The current symbol preference is a `BR` monogram. Treat that as a working
decision, not permission to type two letters and decorate a container. Explore
materially different custom relationships between the letters and always pair
the monogram with the `BrowserRig` wordmark while recognition is being built.

The requested “high-end” quality should come from proportion, spacing,
letterform authorship, negative space, and a coherent application system. It
must not be simulated with gold, fashion styling, hairline detail,
glassmorphism, or luxury-product mockups.

Explore semantic territories such as transfer, a controlled passage, two
systems meeting, rails or rigging, a browser viewport, or a deliberate handoff.
These are prompts for different structures, not a checklist to combine into one
busy symbol.

No palette is approved. Explore outside purple first. Test one accent against a
small neutral system rather than presenting color as the concept. Use color
contrast appropriate to the final context and test the mark in one color before
accepting it.

## Existing Drafts

The following files document rejected or unapproved exploration:

- `extension/icons/icon.svg` and its PNG exports: generic purple `B` tile.
- `docs/chrome-web-store/small-promo.svg`: purple AI-product presentation.
- `docs/chrome-web-store/icon-coupler-concept.svg`: orange terminal/browser
  coupler concept that did not resolve into an attractive mark.

Preserve them until the user approves replacements, but do not treat their
geometry or colors as constraints.

The current extension also uses purple for its tab group and attachment badge.
That is shipped UI state, not permission to carry purple into the new identity.
Do not recolor it inside a purported screenshot. If an approved palette no
longer matches the runtime UI, identify the runtime color change as a separate
implementation task before capturing final Store screenshots.
